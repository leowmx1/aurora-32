# LDMA 独立内核态测试

将 `build/dma_test.hex` 单独加载到 **ROM**，PC=0 复位运行，不运行正式内核或用户程序。
程序初始化内核栈并关闭中断；无需 tick/键盘/DMA ISR，结束后保持空循环，不停止电路时钟。
正式内核装载器现已使用相同 LDMA 协议；本文件是独立硬件测试，不依赖正式内核。

## 已确认的接口

| CPU 字地址 | 寄存器 | 内容 |
|---|---|---|
| 0x0C000000 | origin | Storage 内部低 24 位起始字地址 |
| 0x0C000001 | target | UROM 内部低 24 位起始字地址 |
| 0x0C000002 | len | 复制字数（不是字节数，也不是末尾下标） |
| 0x0C000003 | stat | 写 1 启动；读 1 忙，完成后自动归 0 |
| 0x0C000004 | sum | 写入触发 CS_DMAsum+WE 清零；读出 UROM 写入后的读回累加和（模 2^32） |

先写 origin/target/len，写 sum=0 并读回确认零，再写 stat=1；空闲后先读取 SUM，再比对内容。
SUM 必须来自 UROM 实际读回，流水线最后一字累加完成后才允许 stat=0；首个无效读回不得累加。
测试依旧保留 CPU 逐字检查和哨兵检查，用于独立验证硬件，正式内核则使用 SUM 验证 UROM。
硬件应每个搬运字只加一次，完成时包含最后一个字，结果保持到下次手动清零。
测试不假设写 stat=0 能停止，不测试零长度、越界或忙时再次启动。

## 装载与保护范围

- Storage B 段可以保留现有 `storage/build/storage.hex`，本测试**没有任何 Storage 写入**。
  已有程序/文本文件不需要改动。建议保留有非零和不同内容的镜像，增加数据总线覆盖。
- UROM 至少需要 16,384 字 RAM。本测试改写的最高内部地址为 12,287（含哨兵）；
  不执行其中的数据，测试后重新加载正式 kernel.hex 并复位才能恢复系统。
- 读取前 8,192 字内的若干 Storage 区间；KRAM 中保存最多 4,096 字的比对快照。
- 不改电路、微码和正式系统镜像。

## 测试顺序（均为内部十进制字地址）

| 测试 | origin | target | len |
|---|---:|---:|---:|
| 1 | 0 | 0 | 1 |
| 2 | 1 | 63 | 2 |
| 3 | 31 | 255 | 17 |
| 4 | 251 | 4093 | 257 |
| 5 | 4096 | 8191 | 4096 |

每次保存源数据，给目标写入按位取反的数据并读回确认 CPU 写入生效，然后启动 DMA。
完成后逐字检查目标、源数据未变及目标相邻哨兵，覆盖首字/末字、非零偏移、跨边界和连续启动。
若源全零仍能识别 DMA 没有复制，但不能充分发现源地址选择错误；推荐加载正常存储镜像。

成功终端显示五次 `PASS copy+guards+sum`，最后 `LDMA ALL PASS (5 tests).`。
`DMA elapsed` 是写启动前到检测到完成的 timer 毫秒数，不含准备/比对/输出；
很短的复制显示 0 ms、busy polls 为 0 都可能正常，最终以内容比对为准。
`FAIL address=... expected=... actual=...` 给出首个错误的完整 CPU 字地址和数据。
地址为 `0x0C000004` 表示 SUM 清零或累加结果不正确。
busy 持续 30 秒或累计一百万次轮询则报超时并停止提交任务，需手动复位。
若 DMA 使 CPU 总线完全无法运行，软件也无法输出超时，需要检查电路。

编译：

```powershell
.\build-tools\compile.ps1 tests/dma/dma_test.c tests/dma/build/dma_test.hex -Mode kernel
python tests/dma/run_dma.py
```

Python 仅验证生成 BIN 与理想 DMA 协议，并注入故障验证检测逻辑；不代表 Digital 电路时序通过。
