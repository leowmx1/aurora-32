# 四位地址译码 / 位图绘制：独立内核态测试

将 `build/bitmap_test.hex` **单独加载到 ROM，从 PC=0 复位运行**。
无需正式 kernel.hex，也不执行 UROM。程序初始化 KSP/KFP 并关闭中断，直接访问图形设备。
不需要键盘、MIDI、tick ISR 或图形完成中断。timer 0x08000000 用于 10 秒超时检测。
本测试独立于正式内核；正式内核现已支持同一协议，用户接口见 docs/kernel/graphics.md。

## 地址与假设

图形基址 `0x09000000`，低四位选择寄存器。CPU 是字寻址，偏移不乘 4。

| 偏移 | CPU 字地址 | 含义 |
|---|---|---|
| 0 | 0x09000000 | x |
| 1 | 0x09000001 | y |
| 2 | 0x09000002 | w |
| 3 | 0x09000003 | h |
| 4 | 0x09000004 | c，前景色 |
| 5 | 0x09000005 | bgc，背景色 |
| 6 | 0x09000006 | datalow，bit 0..31 |
| 7 | 0x09000007 | datahigh，bit 32..63 |
| 8 | 0x09000008 | mode：0 矩形、1 双色位图、2 透明背景位图 |
| 9 | 0x09000009 | stat：写 0 停止，写 1 启动；读 1 忙、完成自动归 0 |

沿用此前建议的位顺序：左上角对应 bit 0，先从左向右再逐行向下。
位号 `i = y_local*w + x_local`，前 32 位来自 datalow、后 32 位来自 datahigh。
mode 1 的 0 位写 bgc；mode 2 的 0 位不写显存（不是写颜色 0）。
测试假设位图的 w/h 决定行宽和行数，且 w*h <= 64；没有缩放或自动平铺。
若硬件采用不同的位顺序、固定八位行距或 stat 协议，需要明确约定后调整测试。
矩形 mode 0 不受 64 位容量约束，忽略 datalow/datahigh/bgc。

每个任务开始前确认空闲，写 stat=0，再按偏移 0..8 写入全部参数，最后写 stat=1。
轮询 stat 等完成后才提交下一任务；不要求一定先读到 1，小任务可在首次查询前已完成。
10 秒不完成时打印任务序号并停止提交，空转保留现场，不尝试覆盖仍在工作的设备。

## 应看到的画面

整屏白底。颜色沿用基础调色板：0 白、1 黑、2 红、3 绿、4 蓝、5 黄。
所有图案只画一遍，正常完成后终端显示 `Bitmap smoke DONE. Check screen.`，随后 NOP 空转，
不 HALT、不重画，以免掩盖后续任务破坏前面图案的问题。
DONE 仅表示所有任务的 stat 已归零，程序不能回读显存确认硬件实际画对。

上排从左到右：

1. (16,12) 的 24×24 蓝色矩形：测试 mode 0，尽管 data=0、bgc=红，仍须全蓝。
2. 绿色底板上、(56,20) 的 8×8 红色 F，F 外的位图区域必须为蓝色：测试 mode 1。
3. 绿/黄双色底板上、(104,20) 的同一个红色 F：测试 mode 2，空白位必须保留下面的绿/黄。
   随后用全零透明位图覆盖同一区域，画面必须完全不变，即使 c/bgc 都设为黑。

F 的两字数据为 `datalow=0x1F01013F`、`datahigh=0x00010101`：

```text
######..
#.......
#.......
#####...
#.......
#.......
#.......
........
```

下排从左到右：

| 位置/大小 | 预期 | 检查内容 |
|---|---|---|
| (16,56), 8×8 | 上四行红、下四行蓝 | datalow 全 1、datahigh 全 0 |
| (40,56), 8×8 | 上四行蓝、下四行绿 | datalow 全 0、datahigh 全 1 |
| (64,56), 8×8 | 白底，黑点位于 (71,59)、(64,60) | bit 31 / bit 32 交界 |
| (84,56), 5×7 | 白底，黑点位于 (84,56)、(88,62) | 非 8 像素行宽，bit 0 / bit 34 |
| (96,56), 24×16 | 实心绿色矩形 | 从透明模式切回矩形模式 |

屏幕最右下角 (159,99) 另有一个红像素，测试 1×1 透明位图及边界。
这些小图案按原生像素绘制，不假设硬件缩放；可放大 Digital 显存窗口观察。

## 构建与验证

在项目根目录运行：

```powershell
.\build-tools\compile.ps1 -SourceFile .\tests\graphics-bitmap\bitmap_test.c -HexFile .\tests\graphics-bitmap\build\bitmap_test.hex -Mode kernel
python .\tests\graphics-bitmap\run_bitmap.py --preview
```

产物 s/o/bin/hex 位于本目录 build/。Python/Pillow 仅用于测试/预览，不是编译或硬件运行依赖。
去掉 `--preview` 后不需要 Pillow。
测试执行真实生成的 BIN，核对 14 次任务的地址、数据、写入顺序、像素与透明保留、
立即/延迟完成、timer 回绕、卡忙超时及结束后不再绘制；断言不进入用户态、不执行 INT/EI/HALT。
这是理想 ISA/设备模型，不能代替 Digital 中的译码、位移、WE 时序和真实显存验证。

测试完可直接加载重新构建的正式 kernel.hex 和配套 UROM，无须切回旧硬件协议。
