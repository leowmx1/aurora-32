## 2026-10-18：修复点号 API 封装的批间性能回退

原 `system.io.buffer.*` 在优化阶段仍是间接调用，直到后端分配全局地址前才解析成直接调用，
错过内联/特化。新 `AuroraResolveAPICallsPass` 在优化管线开始与早期简化后解析常量函数表，
保留点号接口、缓冲布局、检查和 64 字批量限制。只处理非 volatile/非原子的确定常量函数入口，
不把动态、可变、可替换的表当成固定入口。

以同一个旧内核 BIN、固定 timer=1234、首个 tick 启动用户后不再注入 IRQ 做控制对照。
两个用户 BIN 均输出完全相同的首帧，批次为 64/64/64/64/64/8，共 328 字符。
从前批最后一次终端 MMIO 写入到后批 INT 的 Aurora 指令数如下：

| 批次间隔 | 优化前 | 优化后 |
|---|---:|---:|
| 1 → 2 | 6630 | 3855 |
| 2 → 3 | 6551 | 3848 |
| 3 → 4 | 6601 | 3740 |
| 4 → 5 | 6082 | 2851 |
| 5 → 6 | 909 | 489 |

五个间隔合计 26773 → 14783，减少约 44.8%。这是指令模型结果，不是 Digital 微码周期或墙钟耗时。
`programs/snake/tests/measure_buffer.py` 可传入同内核的多个 snake BIN，自动校验首帧与批次一致；
默认仅保留启动用户所必需的第一个 tick，避免调度干扰性能对照。正常应用没有关闭 tick。

更新并打包 clang/llc/opt，重建内核、全部七个用户目标及两个契约测试。
**本轮实际入口为 0x000016FE，需一起加载新 ROM 和 UROM，不能混用此前 0x000014DE 的镜像。**
脚本仍按 kernel.o 的符号自动取值，没有硬编码新地址。

验证结果：

- Clang 新增嵌套 API 内联回归通过：确认生成加法而非函数调用，并检查可变/volatile/weak/动态入口不被替换。
- O0 IR 经 opt 的默认 O2 管线及 IR verifier 通过；基础 CodeGen、ALU、条件码回归通过。
- 原生迷宫/终端/kbqueue/贪吃蛇测试通过。
- 实际新 kernel+user BIN：终端 195 次 tick/48 次键盘 IRQ，迷宫 36 步/281 次 tick，
  贪吃蛇 20 帧/121 次 tick/72 次键盘 IRQ；缓冲 API 与 Telnet 契约测试通过。
- `programs/common/tests/run_core_examples.py`：计算器及 trace 的两个表达式与 Q 退出、
  猜数字负数上下限及胜利、五子棋两种坐标写法/交替落子/五连胜利均通过。
- 旧 `aurora_self_test.ps1` 全量脚本在 aurora-api.c 因缺少 _start 无法分配全局量而中断；
  同样调用旧打包编译器也可复现，不是本轮引入。未把全量自测标为通过，也未改变旧断言绕过它。

上述验证不替代真实电路测试。内核源代码、设备协议和微码未因这次优化而更改。
