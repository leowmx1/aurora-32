# Aurora-32 架构与编程约定

本文依据当前 Aurora LLVM/Clang 目标实现、用户库和内核源代码整理；硬件时序仍以
电路和对应微码为准。旧 customasm 规则不完整，不再作为现行 ABI 的唯一依据。
[旧指令手册](legacy-instruction-set.md) 仅保留作历史参考，其中旧用户地址不得用于新代码。

## 机器模型与字地址

数据通路宽 32 位，r0-r15 共 16 个通用寄存器；SP、FP 和 FLAGS 是专用状态。
CPU 原生地址递增 1 对应一个完整 32 位硬件字，不是 PC 机的一个 8 位字节。
普通指令通常 1 字，带完整立即数/地址的指令通常 2 字。

LLVM 的对象文件、节偏移和符号仍使用字节计数。例如 `llvm-nm` 显示内核函数符号
0x100 字节，其 ROM 字地址是 0x40。用户 UROM 基址 0x80000000 字对应
0x200000000 字节，因此用户入口汇编使用 `_start+8589934592`。
“CPU 地址是 32 位”不意味着 ELF 表达式中的代码基址也写成 0x80000000 字节。

不要把 MMIO 常量先乘 4 再传入 `aurora.Read/Write`，也不要拿 nm 输出直接作为 INT 地址。
构建脚本负责必要的转换；C 指针索引由定制前后端实现硬件字步长。

## 地址布局

| 区域 | CPU 字地址范围/设备地址 | 用途 |
|---|---|---|
| ROM | 0x00000000–0x00ffffff | 内核程序、复位入口 |
| RAM | 0x01000000–0x01ffffff | 内核数据 |
| KStack | 0x02000000–0x02ffffff | 内核栈、各进程陷入现场 |
| IVT | 0x03000000–0x03ffffff | 硬件中断向量空间 |
| Keyboard | 0x04000000 | 键盘设备 |
| Terminal | 0x05000000 | 终端设备 |
| Telnet | 0x06000000 | 网络终端设备 |
| tick | 0x07000000 | 调度中断源，读应答 |
| timer | 0x08000000 | 系统毫秒计数，模 2^32 |
| Graphics | 0x09000000–0x09000009 | 低 4 位选 x/y/w/h/color/bgcolor/dataLow/dataHigh/mode/stat |
| MIDI | 0x0A000000–0x0A00007F | 低 7 位为 N；数据为力度/OnOff/PC |
| UROM | 0x80000000–0x80ffffff | 用户代码 |
| URAM | 0x81000000–0x81ffffff | 用户数据 |
| UStack | 0x82000000–0x82ffffff | 用户栈 |

以上为地址分区，不保证电路实装存储器覆盖每个字。实际容量应检查器件配置。
0x08000000 现在是内核 timer，不是用户代码入口。
用户态不能据此认为所有低地址可读；当前 OS 通过系统调用访问内核设备。
图形偏移 5/6/7 分别为背景色、位图低/高字；偏移 8 选矩形/双色/透明模式，
控制偏移 9 写 0/1，完成自动清零。位图至多 64 像素，bit0 为左上角，按自身宽度逐行排列。
旧分散图形地址和旧 MIDI 0x0F 段已停用；硬件译码必须与新内核匹配。

## 模式声明与静态数据

文件作用域声明 `AURORA_KERNEL_PROGRAM;` 或 `AURORA_USER_PROGRAM;`，宏生成
保留的 `__aurora_program_mode` 常量，0 为内核，1 为用户。
后端读取此声明统一决定代码基址、全局数据区和 `_start` 的栈基址。
未声明时默认内核态地址布局，仅用于旧程序兼容；新用户程序必须显式声明。
普通的 `#define USER` 或 `#define KERNAL` 不能自动替代这个被当前后端识别的标记。

全局对象按名称排序，从所选 RAM 区域高端向下分配并满足其对齐。
初始化由后端插入 `_start`；因此定义全局变量的完整镜像必须有 `_start`。
全局地址替换前必须先处理优化器产生的 `or disjoint`：LLVM 的字节对齐推导不能直接
用于打包后的硬件字地址。现行后端先将这种 OR 规范化为 ADD，再替换全局地址；
否则低位常量折叠可能使数组元素互相覆盖。普通位 OR 保持原语义。
较大零初始化可调用生成的 `__aurora_zero_words`。
`.noinit` 对象仍分配地址，但跳过启动时逐字清零，程序必须先维护有效长度/索引，
再访问已写入元素。它不代表多次上电后数据有可信初值。

字符串常量和静态对象也受此机制影响，不能机械套用通用 ELF 装载器的 `.data/.bss`
假设。当前构建可以直接提取已解决内部地址的 `.text`，正是依赖这些定制规则。

## C 类型与限制

`int`、`short`、`long` 的当前目标宽度均为 32 位，指针与寄存器参数也为 32 位。
结构体、固定大小数组和普通函数已经用于实际 PCB/示例代码。
硬件统一字访问不等于当前前端已经对所有 C 类型消除窄 IR：`char` 数组写入仍可能
生成 i8 truncstore 并触发 `Cannot select`。可写字符缓冲用 `int[]` 是现有示例的稳妥写法。
字符串字面量加 `system.io.PutString` 与可写 char 数组是不同路径。

不能把 `sizeof` 的 LLVM/C 字节量不加判断地当成硬件字地址；栈空间和结构体偏移
由定制代码转换。不要混用宿主编译器生成的对象与 Aurora 对象。
不承诺支持浮点运行库、可变参数、动态栈数组、TLS、异常处理、动态链接或完整 C++。
普通 `printf/malloc` 没有配套运行库；使用项目 API 和静态空间。

## 调用 ABI

| 寄存器 | 约定 |
|---|---|
| r0-r3 | 普通 C 前四个标量参数 |
| r0 | 普通 32 位返回值 |
| r4-r9 | 普通调用的被调用者保存寄存器 |
| r0-r3、r10-r15、FLAGS | 普通 CALL 可破坏，调用者有需要则保存 |
| r14/r15 | 后端保留的临时寄存器，不应随意用于长生命周期内联汇编值 |
| SP/FP | 通过专用指令访问；KSP/KFP 与 USP/UFP 按权限隔离 |

额外参数使用栈槽；LLVM 描述槽位为 4 字节，映射到一个硬件字。
系统调用是另一份约定：r0 请求号/返回值，r1-r3 参数，见 [内核 ABI](../kernel/README.md)。
内联汇编必须声明真实输入、输出、寄存器和内存副作用；不能假定异步回调是普通 CALL。

栈向高地址增长。普通 CALL/RET 操作当前模式栈，函数可能使用 PUSHFP/STF/FTS/POPFP
构建帧。`_start` 没有调用者，编译器必须先设置 SP/FP，再执行所有使用栈的操作。

## FLAGS、INT 和硬件中断

Z/C/N/V 表示算术状态，保存的 P 表示内核态 1、用户态 0。电路内部权限寄存器若采用
相反极性，保存/恢复时必须进行正确转换，不能直接混用内部寄存器位和外部 kernelmode。
比较后条件跳转要使用同一次比较产生的 FLAGS，不能被中间的算术指令覆盖。

INT 的地址就是 ROM 处理函数起点；硬件 IRQ 则通过 IVT 查目标。
中断进入必须先保存原 FLAGS/P 的值，然后选择内核栈压 FLAGS、PC。
IRET 必须恢复 PC 后再恢复 FLAGS/P。内部临时模式变化（例如 PUSHU/POPU）不能破坏
当前微指令控制源或原状态锁存；仅看到 PC 未跑飞不足以证明返回现场完整。

IRQ 请求和向量号需要保持到控制序列消费/应答，不能只发一个在查向量前消失的脉冲。
用户异常检测也应限定在真正由用户发起的有效访问阶段，不能误将中断切模式、
预取、片选未稳定或总线高阻阶段当作用户非法访问。具体逻辑需结合电路验证。

## 编译器如何生成机器码

Clang 完成词法/语法、类型检查、Aurora builtin 和字寻址相关转换，产生 LLVM IR。
后端执行全局分配和合法化、选择 Aurora 指令、寄存器分配、栈帧生成，最终编码对象。
相关定义集中在 `AuroraProgramMode.h`、`AuroraCallingConv.td`、`AuroraRegisterInfo.td`、
`AuroraInstrInfo.td`、`AuroraISelLowering.cpp`、`AuroraFrameLowering.cpp` 和 MC 层。
这些源文件位于维护中的 LLVM 仓库，随项目提供的是可运行工具快照，非完整 LLVM 源码。

Aurora 没有条件移动指令。比较值/三元选择经自定义 SELECT_CC 和伪指令展开成
CMP、条件分支及合流值。旧实现将 SETCC/SELECT/SELECT_CC 都标为 Expand，会循环
合法化，表现为编译器 CPU 忙且无输出；当前快照包含该修复。
修改 TableGen 定义后必须重新生成表并重编全部受影响的 Aurora 对象，再链接工具，
混用不同生成枚举的对象可能产生难以理解的指令错误。
