# EEPROM 存储、可执行文件和系统终端

更新：2026-11-01。当前为 **ASFS2 目录与文本读写 + AEXE1 独立可执行格式 + LDMA 固定地址装载器**。
新格式、quickrun、文件管理和系统调用详见 [ASFS2](filesystem-v2.md)。下文保留 AEXE 和旧 ASFS1 格式说明。
不是 FAT，也不是 HEX 文本拼接；新版内核仍可以只读挂载旧 ASFS1。

## 硬件接线与加载

- EEPROM 接 `0x0B000000` 段，地址低位选择存储字；数据宽度 32 位。所有偏移、长度都以字计，不乘 4。
- ROM 加载 `kernel/build/kernel.hex`，复位 PC=0。
- 存储 EEPROM 加载 `storage/build/storage.hex`，从器件本地地址 0 开始。
- UROM 仍映射 `0x80000000`，物理设备现为断电归零的 RAM。WE 允许**内核态**写，用户态禁止写。
- LDMA 位于 `0x0C000000..0x0C000004`，依次为 origin、target、len、stat、sum；只允许内核访问。
  源/目标均写器件内部低 24 位字地址，len 为字数。写 stat=1 启动，完成自动变 0。
  每次启动前 CPU 写 sum=0，形成 CS_DMAsum+WE 以清零；完成后读取 32 位 UROM 读回累加和。
- 用户 URAM/UStack 分区不变，旧键盘/Telnet/tick 中断协议不变，不增加 EEPROM 中断。
- 目前接口假定存储读取和 UROM 写入具有和 RAM 相同的总线完成语义。真实器件若需要编程延迟/
  busy/解锁序列，必须增加设备驱动，不能只依靠一次读回。Digital 模型由你的电路保证。
- 本次没有改动 `.dig` 或微码；EEPROM 译码和 UROM 写入权限需要在电路上接好。

已确认存储器实际容量为 **2^24 = 16,777,216 个 32 位字（64 MiB）**，
CPU 字地址范围为 `0x0B000000`–`0x0BFFFFFF`。内核按硬件约定使用该容量，不是运行时探测。
默认镜像实际长度以每次 `storage/build/storage.json` 的 Words 为准，不补满整个设备。
`df` 分别显示设备容量、镜像长度和镜像以外的字数；镜像长度包含目录、预留区和文件。
ASFS2 可以在线创建文本和目录，删除留下的内部空洞也会参与分配；EXE 仍由外部打包加入。
无有效挂载镜像时只报告设备容量，不推断占用。HEX 无需补零到设备全容量。
实际代码长度以构建报告为准，UROM 容量与 storage 容量无关。
打包器默认限制为 16,777,216 字；`-CapacityWords` 可用于测试较小设备。

## 构建和命令

### LDMA 装载行为

`run` 先检查结构、地址和 ABI，再显示 Copy、Verify；不再执行独立的 Check 或 CPU UROM 扫描。
Copy 的代码段由 LDMA 从 Storage 搬到 UROM，并取得每个任务的实际 UROM 读回 SUM。CPU 只对没有被代码
DMA 覆盖的文件字求和（文件头、段表、数据、间隙和尾部填充），加上所有代码 SUM，按模 2^32
与目录中的整 AEXE 校验和比较。段表可以不按源地址排序，不更改 ASFS/AEXE 格式。
URAM 数据段与补零仍由 CPU 完成并读回检查；补出的零不属于文件，不参与文件校验和。
少见的多个代码段共享/重叠源区间时，仅由 CPU 对重叠部分减去重复计入的源字和；
所有目标副本仍参与 LDMA SUM，没有整文件 CPU Check 回退。
`quickrun` 保留格式、地址、ABI 等检查，跳过校验和比较及 CPU URAM Verify；每个 DMA 任务仍清零、
读取 SUM，硬件自身的流水读回仍会执行。
独立的 `verify NAME` 命令检查存储文件，仍使用整文件 CPU 校验，不发 DMA、不改变 UROM。

正常单代码段在加载过程中完全不由 CPU 扫描代码源/目标；Verify 比较组合后的整文件校验和。
若 SUM 不匹配，会报告 Expected/Actual 校验和并拒绝启动。因为 SUM 在复制时得到，失败时
UROM 可能已被覆盖，但不会创建用户上下文或执行其中内容；可重新加载有效程序。

一个代码段通常只提交一次 DMA；Copy 进度由 0% 直接到 100%，因为硬件没有进度寄存器，
软件不伪造中间百分比。完整 2^24 字的极限段分成两个非零任务，避免长度超过 24 位。
所有段先完成结构/边界/重叠检查，DMA 结束后才读下一个段或创建用户上下文。
等待期间保留 tick、键盘、Telnet IRQ；ISR 不访问 DMA 正占用的 Storage/UROM。

DMA 等待超过 timer 30 秒或一百万次轮询，或提交时异常 busy，打印错误后刷黑屏并停机，
需手动复位。没有已确认的 abort 协议，不能继续进入终端访问 Storage 或执行半成品。
若总线故障导致 CPU 本身无法执行，软件超时也无法工作。

SUM 必须从 UROM 独立读口取得写入后的数据，每个复制地址累加一次，不能使用 Storage 输出或写入输入。
流水线首个无效读回不能累加；stat 归零前必须完成最后一字的读回与累加，不能只等最后一次写入。
SUM 保持到下次显式写入清零；普通 CPU Storage/UROM 读取不应改变它。
旧版源数据 SUM 硬件不再满足此内核的验证契约，不能代替新的目的读回 SUM。
累加和不是密码学校验，也不能识别所有重排/相互抵消的错误。
此内核需要已通过 smoke test 的 LDMA 电路；更新 kernel.hex 即可，不改变 ABI 或存储格式。

```powershell
# 一次构建内核、全部用户程序、存储镜像
.\build-tools\build.ps1
# 程序已构建时，只重新打包
.\build-tools\pack-storage.ps1
# 自定义清单/输出；HEX 路径相对清单所在目录
.\build-tools\pack-storage.ps1 -Manifest .\storage\programs.json -OutputFile .\storage\build\storage.hex
```

清单 `storage/programs.json` 使用 Version=2、DataOffsetWords、Files；EXE 项为 Name/Hex，TXT 项为 Name/Type/Source/ReserveWords。
文件名 1..31 个小写 ASCII 字母、数字、点、下划线或连字符，不能重复或使用 shell 保留命令名。
每个 HEX 必须伴随编译器构建流程生成的同名 `.program.json`；脚本核对 SHA-256、长度、入口、
ABI 和固定 INT 跳板，拒绝旧地址镜像或被手改后未重建的 HEX。支持 v2.0 raw 的字和十进制重复计数。
构建不依赖 Python；模型测试需要 Python。

开机显示 `aurora:/ > `，支持（完整列表见 `help`）：

```text
ls
run calculator
snake
maze
gomoku
tetris
help
mount
halt
```

`ls` 显示文件名及可执行容器长度（含文件头）；`run NAME` 与直接输入 NAME 等效。
Enter 支持 CR、LF、CRLF，Backspace/Delete 编辑，命令最多 63 字；超长整行拒绝执行。
程序自己处理 Q/exit 等退出操作，`system.Exit(code)` 后返回 `aurora:/ > `；系统终端不劫持运行中程序的按键。
本地 `aurora:/ >` 和远程 `aurora:remote:/ >` 都由内核提供；mini-terminal 示例已移除。
`mount` 允许没有有效镜像时重试；只能在没有用户进程的终端状态下替换镜像并重新 mount，不能运行中热换。

## 四层边界

| 文件 | 责任 |
|---|---|
| `kernel/storage.h` | 字设备读取及不溢出的范围检查，唯一知道 B 段基址的层 |
| `kernel/filesystem.h` | 挂载、目录验证、按名称打开文件、按文件偏移读取、列目录 |
| `kernel/loader.h` | 校验 AEXE、段边界/权限、ABI/入口/校验和，复制、清零、读回验证 |
| `kernel/ldma.h` | LDMA 提交、SUM 手动清零/读回、完成轮询和超时停机 |
| `kernel/shell.h` | 命令行、列文件、发起加载；不直接决定文件的 EEPROM 地址 |
| `kernel/kernel.c` | 创建用户现场、调度、事件、正常退出返回 SYSTEM、异常蓝屏停机 |

头文件组织是为了沿用当前单翻译单元工具链，不表示设备/文件系统/加载器共享一种格式。
ASFS2 已加入写入和子目录，`file_api.h` 提供用户接口；其他介质、重定位/多进程仍需要独立设计。

## ASFS v1 磁盘格式（旧镜像只读兼容）

所有字段是 32 位字。HEX 每个八位十六进制 token 表示一个字；名字每字一个 ASCII 字符。
文件偏移相对镜像开头，段文件偏移相对 AEXE 开头，均不是 CPU 绝对地址。

16 字超级块：

| 字偏移 | 内容 |
|---|---|
| 0 | magic `0x41534653`（ASFS） |
| 1 | 版本 1 |
| 2 | 头长 16 |
| 3 | 整个镜像长度 |
| 4 | 文件数，最多 64 |
| 5 | 目录起点（默认 16） |
| 6 | 目录项长度（默认 40，v1 接受 40..256，扩展字必须零） |
| 7 | 内容区起点（默认 4096，内核读取此值，不写死） |
| 8 | 格式标志 1：只读平面目录 |
| 9..15 | 保留，必须零 |

目录项：0=类型（1 可执行），1=文件起点，2=文件长度，3=整个 AEXE 所有字相加模 2^32，
4..35=32 字文件名空间（必须零结尾，尾部全零），36..39=保留零。
挂载拒绝越界/重叠文件、重名、非法名字、目录与内容区重叠、不支持的版本/类型/标志。
空目录允许挂载，但当前打包脚本要求至少一个程序。

## AEXE v1 可执行格式

16 字头：

| 字偏移 | 内容 |
|---|---|
| 0 | magic `0x41455845`（AEXE） |
| 1..3 | 版本 1、头长 16、文件总长度 |
| 4 | CPU 字地址入口，当前包为 `0x80000000` |
| 5 | 系统调用 ABI 版本 3 |
| 6 | 系统调用跳板字地址 2 |
| 7..9 | 段数 1..8、段表偏移、段项长度 6 |
| 10 | 启动契约标志 1：编译器入口初始化全局变量和 USP/UFP |
| 11..15 | 保留零 |

每段六字：目标 CPU 字地址、文件内数据偏移、文件数据字数、内存字数、段标志、保留零。
段标志 1 表示 UROM 代码（文件长度必须等于内存长度），2 表示 URAM 数据（允许后半段清零）。
文件内容不得与头/段表重叠，目标段不能重叠、跨区域或写内核区，入口必须位于某个代码段内。
普通 run 在所有结构和边界检查完成后才写用户存储；复制、清零、整文件校验和及读回都成功后才发布用户进程。
quickrun 保留结构与边界检查，但跳过校验和及拷贝后读回，仅用于已知正确的可信镜像。
失败留在终端，用户永远不进入半加载镜像；但已经写入的用户内存不回滚。

目前打包器生成一个代码段（22 字元数据后跟 HEX 内容）；当前后端把全局数据初始化编译成 `_start`
中的指令，不是 ELF `.data/.bss` 的加载式布局。加载器已经能接受独立数据/零填充段，未来可升级打包器。
旧 UROM 尾部、未用 URAM、`.noinit`、旧用户栈不整区清零；当前系统仅运行可信本地程序，
**不提供进程之间的保密隔离**。普通全局变量由入口重新初始化，`.noinit` 仍按未初始化内存处理。
校验和只用于发现普通损坏，不是密码学签名，不能安全执行恶意镜像。

## 固定系统调用入口

ROM 字 0..1 是 `JMP aurora_reset_entry`（建立栈并打印早期日志后跳 `_start`），字 2..3 是 `aurora_syscall_gateway: JMP aurora_syscall_entry`。
所有新程序执行 `INT 2`，仍然是直接 ROM 地址，不是中断向量表项。
构建从 kernel.o 检查跳板位置并写入构建元数据；内核内部增减函数不影响用户 INT。
保持跳板、ABI 语义和内存布局时可复用已打包程序；未来不兼容变更应升级 ABI/格式并拒绝旧程序。

## 生命周期与限制

系统终端只在用户无效时读取键盘队列，ISR 只入队。加载过程用户不可运行、保持 IRQ 开启；
发布新 PCB 时短暂关中断，返回 `_start` 主循环后才开中断，避免 SYSTEM 的保存现场留在加载器栈内部。
初始化重置寄存器、事件 FIFO、订阅、回调、Sleep、输入序号；用户入口负责 USP/UFP 和全局初始化。

正常退出通过 syscall 尾部切回保存的 SYSTEM 完整现场；用户保护异常通过专用裸入口放弃用户现场，
显示蓝屏后 HALT，不再返回终端。两者都会清理 MIDI、停止旧显存任务、取消回调和休眠并丢弃旧输入。
输入已经进入旧用户队列的字符不会传给新程序；程序退出后才到达的硬件键是新的终端输入。
系统异常仍 HALT。当前沿用原异常硬件协议，没有凭空增加异常应答地址或修复持续电平 IRQ。

这是串行程序加载，不是动态链接，也没有并行用户进程或内存保护升级。所有程序仍占相同 UROM/URAM。
测试/调试可用 `kernel/build.ps1 -DirectBoot -OutputDirectory ...` 生成预加载 UROM、退出停机的专用内核；
生产默认始终进入系统终端，即使 B 段无镜像也不会执行残留 UROM。
