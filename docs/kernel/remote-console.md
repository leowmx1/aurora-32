# 本地与远程系统终端

两个终端属于同一个 SYSTEM 进程，各可运行一个前台和一个后台用户程序，共四槽。
详细约定、地址和测试见 [用户银行与多进程](user-banks.md)。

| 端点 | 输入 / 输出 | 提示符 |
|---|---|---|
| 本地 | 键盘 IRQ / 终端 MMIO | `aurora:/ >` |
| 远程 | Telnet IRQ / Telnet MMIO | `aurora:remote:/ >` |

Telnet 数据地址 `0x06000000`、硬中断向量 `0x03000002` 不变。
每端有独立的命令行、CRLF 状态、最近十条命令历史和提示状态。
`history` 从新到旧显示：1 为最新，最多到 10；满十条后覆盖最旧记录。
`!1` 或 `!!` 重复最新命令，`!10` 重复当前最旧的一条（须已保存十条）。
`history` 本身和无效的历史引用不入历史；成功重放的命令作为最新记录保存。
远程终端由内核回显，客户端应关闭本地回显；输出 LF 转为 CRLF。
当前按设备提供的原始字符流处理，不实现 Telnet IAC 协商、认证、加密或连接状态探测。
仅用于可信模拟环境，不要直接暴露到不可信网络。

## 程序的终端归属

在哪一端执行 `run`、`quickrun` 或程序名称，程序就归属哪一端：

- `system.io.PutChar/PutInt/PutString/Write` 输出到程序所属端。
- `system.io.Subscribe` 订阅所属端的输入；远程输入也转换为标准 A5 键盘事件。
- `system.io.GetChar` 读取所属端的未订阅输入队列。
- `NAME &` / `run NAME &` 后台启动；另一端可独立启动自己的用户程序，不覆盖已有银行。
- 后台没有终端输入权限，Subscribe/GetChar 返回 EBUSY。用户终端输出静默丢弃，有效请求仍返回成功（Write 返回字数）；内核的退出/故障通知仍显示。
- 前台可用 `system.Background()` 主动转后台，原槽位不变，输入交还系统；已有后台则 EBUSY。
- 前台 `system.Exit` 后，原端恢复系统欢迎信息和提示符，另一端的命令行/历史保持不变。
  后台退出只发具名通知，不中断当前前台程序。
- 显存和 MIDI 仍是共享硬件。远程启动屏幕游戏，画面仍出现在 Digital 显存窗口，
  不是通过 Telnet 传输图像。另一端的 `clear` 不会覆盖活动游戏画面。

`ps` 显示每槽的程序名、编号、银行、终端、前后台、等待/退出状态和退出码。
`kill SLOT` 终止指定的 1..4 槽，退出码 137；仅取消目标拥有的 MIDI、GPU、回调和等待。
所有退出立即向所属终端报告姓名和槽位等信息，即使前台用户仍运行；后台退出不重画前台。
`kill` / `kill user` 只在恰有一个用户运行时兼容，无用户则报告 `No user program running.`。
强制终止不会保存 editor 未保存草稿；没有文件系统事务保障。
`halt` 是全系统停机，不只是关闭当前终端。

## Telnet 独占与统计

Telnet 现在专用于系统终端。旧 `system.telnet` 的读、写、订阅四个请求保留编号，统一返回
`AURORA_EBUSY`，不读写设备、不注册回调。`send` 命令及 mini-terminal 示例已移除。

`netstat` 显示：自复位以来 RX/TX 字节数、最近收发的 timer 毫秒值、RX 队列待取数与丢弃数、
键盘队列丢弃数。计数包括 CR/LF、远程欢迎信息、提示符和回显，按模 2^32 回绕。
TX 仅表示已写设备，不代表网络交付成功；RX 是设备 IRQ 读出的字节数，含随后因队列满而丢弃的字节。
没有丢弃时 drops 保持 0 完全正常，不能用它判断有没有流量。
统计取短暂关中断的一致快照，然后开中断打印；远程执行 netstat 自己也会产生 TX。

## 调度及文件安全

SYSTEM 每次服务两个端点，各取至多一个输入字，再在有可运行用户时主动 Yield。
tick 正常抢占，用户 WaitEvent/Sleep 仍有效。ISR 只读设备、排队和准备符合条件的回调，
不执行系统命令。当前命令执行仍是同步的；较长的 verify/装载期间，另一端的系统命令会排队，
不是两个命令解释器并行执行。除 LDMA 占用总线期间，用户仍可被 tick 调度。

系统命令处理期间预留文件系统工作区；此时用户文件系统调用返回 EBUSY，应稍后重试。
通过 Open/Info/List/Read/Save 暴露给当前用户的文件 ID 会保留到用户退出；另一端不能 rm
这些条目，避免删除后复用同一个 ID 使编辑器覆盖另一文件。rename/mv 保持 ID，仍可执行。
未被用户引用的文件可以正常创建、移动、删除。暂没有 Close/解除引用调用。

## 启动及内存设备

复位入口先建立 KSP/KFP，并在自动全局初始化前输出即时数值日志。早期日志不读取任何尚未
初始化的全局变量/字符串。随后初始化内核、自检并直接进入系统终端，**不再等待 3 秒**。
本地欢迎信息显示 `BIOS startup: N ms since reset.`，包括数据初始化、自检和首次图标绘制；
来源是 timer，不是宿主机时间。这里 BIOS 指当前内核启动过程，没有另一个 BIOS 固件层。

UROM 物理地址段为 `0x80000000..0x80ffffff`，每进程逻辑窗口为 `0x80000000..0x803fffff`，
物理设备现为断电归零的 **RAM**。
用户仍不可写，内核从 B 段 EEPROM 装载。关机不额外擦写 UROM；同次开机重载小程序也不清
整个尾部。不能把“物理断电归零”推断成任何软复位操作都会清空。

验证入口：`tests/storage/run_remote.py`。执行真实生成的 BIN，检查两种程序归属、隔离输入输出、
独立历史、CRLF 交接、多银行并发、kill 和文件引用保护；这是理想 ISA/设备模型，不是 Digital 电气仿真。
