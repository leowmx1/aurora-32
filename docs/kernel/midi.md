# MIDI 系统调用

单个 Digital MIDI 模块，通道号在组件属性中固定选择。软件不选择通道，
PC 是 Program Change（切换音色），不是通道地址。本实现无 MIDI IRQ、无硬件 busy 查询、
无音频采样缓冲区。软件序列由现有 tick 驱动，不修改电路或微码。

MIDI 设备基址现为 `0x0A000000`（原 0x0F 段停用）。仅改设备地址，低 7 位 N、
数据力度/OnOff/PC、系统调用编号和 tick 音序逻辑保持不变。需要匹配新的硬件译码。

## 硬件约定

| CPU 字地址/数据 | 含义 |
|---|---|
| `0x0A000000 + N` | N=0..127，地址低 7 位 |
| 数据 `[6:0]` | V，力度 0..127 |
| 数据 `[7]` | OnOff，1 按下、0 松开 |
| 数据 `[8]` | PC，1 时 N 改为零基乐器编号 |

en 接设备片选，C 在每次写入时产生上升沿；该沿到来前地址、数据须稳定，
连续两次写入之间 C 须回到低电平。PC=1 的写入不演奏音符。
例：`[0x0A00003C]=0xE4` 按下 60、力度 100；写 0 松开；
`[0x0A000000]=0x100` 选择音色编号 0。

## 用户接口

包含 `<aurora_system.h>`，通过 `system.midi` 调用：

```c
system.midi.Program(0u);       // 音色编号 0；标准 GM 音色表中为钢琴
system.midi.NoteOn(84u, 100u); // 按下；立即返回，不等待音符结束
// 继续执行游戏/绘图，按 TimeMs 安排结束时间
system.midi.NoteOff(84u);
system.midi.AllNotesOff();    // 释放本内核记录的所有活动音符
```

每个调用返回 0 表示已写入设备，-1 表示参数非法；调用者应检查返回值。
没有设备回读/连接探测，返回成功不保证电脑实际发声或音色可用。
音符、力度、乐器编号均只允许 0..127，内核直接验证完整 32 位参数，
不掩掉高位将非法数伪装为合法数。负数转换为 unsigned 后也会拒绝，且不写设备。

NoteOn 力度 0 等价 NoteOff；同音符重复 NoteOn 时先释放旧音符，再重新按下，
避免叠加而只释放一次。不同音符可同时保持。Program 不自动释放已经按下的音符。
AllNotesOff 遍历 128 个内核记录，仅发送必要的 NoteOff，不切换乐器；它不是硬件
强制静音指令，音色仍可能有释放尾音。非本次内核记录的、复位前残留的声音不在管理范围内。
AllNotesOff 同时取消下面的背景和音效序列。序列存在时，直接 NoteOn/NoteOff 返回
EBUSY=-5，避免用户直接写音符与内核定时播放器争用；先停止序列再直接控制。

内核启动仅清理软件记录，不向未使用的 MIDI 设备写入。正常退出或用户异常停机前，
统一释放活动音符，防止进程结束后留下未松开的键。当前只有一个用户进程/硬件通道；
若将来有多个用户或通道，须扩展设备协议及音符所有权，不能直接共享此数组。

## 寄存器 ABI

| r0 请求 | r1 | r2 | r3 | 返回 r0 |
|---|---|---|---|---|
| 22 MIDI_NOTE_ON | 音符 | 力度 | 未使用 | 0 / -1 / -5 |
| 23 MIDI_NOTE_OFF | 音符 | 未使用 | 未使用 | 0 / -1 / -5 |
| 24 MIDI_PROGRAM | 乐器编号 | 未使用 | 未使用 | 0 / -1 |
| 25 MIDI_ALL_NOTES_OFF | 未使用 | 未使用 | 未使用 | 0 |
| 26 MIDI_SEQUENCE | 用户数组字地址 | 步数 1..64 | 0 单次背景 / 1 循环背景 / 2 单次音效 | 0 / -1 / -4 |
| 27 MIDI_SEQUENCE_BUSY | 未使用 | 未使用 | 未使用 | bit0 背景存在，bit1 音效存在 |

旧系统调用保持不变，21 仍停用，ABI_VERSION 仍为 3。本次是追加接口；旧内核对新请求
返回 ENOSYS。INT 始终使用实际内核入口地址，更新后必须成套加载新 ROM/UROM。
参数经寄存器传递，序列数组仅允许 UROM/URAM，不访问用户栈；MIDI MMIO 仅在内核中、
INT 或硬件 IRQ 已清 IE 时执行。
用户回调可调用 MIDI，但不应该等待音符结束，避免阻塞后续回调投递。

## 音符时长和贪吃蛇测试

直接 NoteOn 的持续时间由用户程序负责，不自动停止。用无符号差值
`system.TimeMs() - start >= duration` 处理计时器回绕；期间 Yield 让出 CPU。
WaitEvent 不是定时睡眠，若音符仍需软件释放且没有其他事件源唤醒，不能直接 WaitEvent。

屏幕贪吃蛇改用下面的内核序列接口，提供开局、背景循环、吃食物、出局和胜利短旋律。
单通道音效暂时冻结背景的时间位置，结束后从原音符的剩余时值继续，不重播开头。
暂停/M 关闭取消全部序列；出局/胜利取消背景，只播短音效，查询完成后退出。
游戏开始前打印一次操作帮助；运行期间不再打印吃食物、暂停、速度和 M 状态，退出时
输出分数/原因，致命错误也会报错后退出。内核自身的启动/异常/退出日志不变。
详细音符和时长见 [贪吃蛇说明](../user_program/snake-screen/README.md)。

## tick 驱动的内核音序器

```c
static const aurora_word_t tune[] = {
  // note, velocity, hold_ms, gap_ms
  60, 42, 300, 100,
  64, 42, 300, 100,
  128, 0, 0, 200, // 128 是休止；真正 MIDI 音符 0 仍合法
};
system.midi.Sequence(tune, 3, 1); // 循环背景，复制后立即返回
// 用户可计算、绘图或等待键盘；播放不需要用户循环逐个发音符。
// system.midi.Sequence(effect, count, 2) 可插播一段单次音效。
int busy = system.midi.SequenceBusy(); // 软件状态，不读取 MIDI 硬件
system.midi.AllNotesOff();             // 停止两个序列并释放音符
```

最多两个内核轨道，每条 64 步、每步 4 个 32 位字，共 512 字数据。
note 允许 0..128（128 休止），velocity 0..127（0 不发声），hold/gap 各 0..60000 ms，
每步总时长必须非零。参数/数组完整区间及每个字段全部检查后才复制和替换轨道；
非法请求不会部分播放/替换。数组必须静态/全局位于 UROM/URAM；内核保存副本，
返回后改动原数组不影响播放。flags 仅 0/1/2，有界拷贝在关中断区执行，没有用户指针留在 ISR。

背景允许单次或循环；音效仅单次。音效优先，首次插播保存背景已播放时间，
连续插播替换当前音效而保留背景冻结位置。音效结束后将背景起点平移音效时长，
继续原音符/休止；同音符恢复可能重新触发包络，但不是曲子从头开始。
替换背景会重置背景位置；若音效正在播放，新背景等待音效结束。AllNotesOff、进程退出、
用户异常会取消两轨，不能让后续 tick 再发声。未使用序列的程序，tick 快速检查后直接返回。

tick 仍先读 0x07000000 应答并保存完整通用寄存器，调度函数再调用 MIDI service。
该服务也在 Yield 调度路径和 SequenceBusy 查询时运行；不依赖用户回调、用户音序循环或绘图。
时间来自 timer 0x08000000，截止点按原始时间线累加，不用“实际执行时间 + 下一音长度”。
正常服务先检查下一期限，未到期不扫描；到期最多扫描所选轨道的 64 步，最多释放/按下一音。
若延迟跨过多个音符，跳过已过期音符，直接对齐当前拍点，不突发补播，不把延迟累积到以后。
无符号差值支持正常运行跨 timer 2^32 回绕；期限有符号比较要求两次服务间隔小于 2^31 ms。

这不等于硬实时：实际触发仍有最多一个正常 tick 周期加关中断/处理延迟的抖动。
tick 应明显短于最短音符，建议约 5..10 ms。若 tick 很慢或内核长时间关中断，仍可能
漏短音；软件不能凭空提高硬件中断频率。绘图设备 busy 本身不会推迟时钟上的拍点，
用户 DeferEvents 也只延迟回调，不禁止 tick 音频服务。序列完成没有事件，若用户需要
等待完成后退出，用 SequenceBusy + Yield，不用无其他事件源的 WaitEvent。

## 构建和验证

`./build-tools/build.ps1` 已重建全部示例，SDK 两份头文件同步。
ROM 加载 `kernel/build/kernel.hex`，UROM 加载
`user-programs/programs/snake-screen/build/snake-screen.hex`，吃到食物听取音效。
MIDI 模块需要启用 PC 输入并接到数据 bit 8，选择正常旋律通道，主机音量不能静音。

`tests/midi-syscall` 执行实际内核/用户 BIN，验证边界和非法参数无写入、位布局、
力度 0、重复音符、和弦、回调、tick、退出及两类用户异常的释放。
`tests/snake-screen` 检查吃食物、暂停/出局的声音处理，保留显示/控制回归，
另有复用真实音序器的完整旋律/计时回绕测试。
`run_sequence.py` 在用户纯计算（无音频查询/Yield）及慢绘图期间验证 tick 独立播放、
原位置续播、固定拍点、输入副本、参数边界，以及 timer 回绕。
这些是理想指令与设备模型测试，不验证 Digital 信号时序、实际发声或音色。
