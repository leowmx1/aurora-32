# 5×5 终端五子棋

源文件：[tic_tac_toe.c](../../../user-programs/programs/tic-tac-toe/tic_tac_toe.c)。
目录和构建目标保留名称 `tic-tac-toe`，但当前规则是 **5×5 棋盘、连续 5 子获胜**，
不是传统 3×3 井字棋，也不是早期的“连 3 子”规则。

## 开局和输入

开局显示空棋盘：

```text
  1 2 3 4 5
A
B
C
D
E
Player 1 >
```

实际每一行还会打印对应空格。Player 1 使用 `X`，Player 2 使用 `@`。
坐标范围为 A–E 和 1–5，支持行列任意先后与小写行字母：
`A3`、`3A`、`a3`、`3a` 均为同一格。

输入满两个合法坐标字符后立即落子，**不需要 Enter**；CR/LF 会被忽略。
输入第一个坐标字符时会回显，尚未提交。例：输入 `E` 后再输入 `5`，落在右下角。
程序没有空格分隔坐标、退格编辑、悔棋或 Q 退出功能。

## 规则与画面

合法落子后清屏（输出 `\f`）、重画棋盘，再提示下一位玩家。
格式错误会清除尚未完成的坐标并显示错误；已占用格不会落子，也不会更换玩家。
因此 `A1` 输入两次，第二次应看到 `That cell is occupied.`。

获胜检查覆盖 5 行、5 列和 2 条长度为 5 的对角线。由于棋盘只有 5×5，
“连续五子”恰好对应一整行、一整列或主/副对角线；短对角线不可能获胜。
每步先检查获胜，再检查 25 格是否全满。无获胜线且全满为平局。

结束时清屏重画最后棋盘，输出 `Player N wins!` 或 `Draw!`，再调用
`system.Exit(0)`。当前内核随后输出退出日志并停机，不会自动开始新一局。

## 代码结构

输出已改为 `system.io.buffer` 的 64 字批量缓冲，棋盘和提示文本、规则均不变。
正常一帧 84 字，由原先 65 次输出系统调用降为 2 次 Write。按键回显仍是单字符输出。
终端不支持任意光标定位，所以仍用 `\f` 清屏重绘，并非局部更新。
请使用新增 Write 接口的配套内核，不要把新用户 HEX 与旧内核混用。

`board[25]` 保存 0/1/2，分别表示空位和两位玩家；`current_player`、`move_count`
维护回合。`pending_row`、`pending_column` 保存只输入一个字符时的状态。
`process_character` 解码坐标，`submit_move` 检查并落子，`has_winning_line`
调用 `line_is_winner` 检查获胜线，`draw_board` / `draw_turn` 负责输出。

键盘回调将事件追加到 32 项环形队列（有效容量 31）；主循环校验签名和 IRQ
序号后处理字符。回调不绘图、不发系统调用、不执行棋局算法。
队列满时丢弃最新事件，没有输入无损保证；建议逐步输入，不连续粘贴整盘坐标。

## 构建与检查

```powershell
.\build-tools\build.ps1 -Program tic-tac-toe
```

加载 `user-programs/programs/tic-tac-toe/build/tic-tac-toe.hex` 到 UROM。
可按顺序输入 `A1 B1 A2 B2 A3 B3 A4 B4 A5` 验证 Player 1 横向获胜。
每对坐标之间这里的空格仅为阅读分隔，实际输入不需要空格；如手动按空格会作为
非法坐标处理。还应验证 `5E`、`e5`、越界 `F1` 和重复落子。
