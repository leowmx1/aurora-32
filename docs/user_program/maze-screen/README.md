# 屏幕版迷宫

## 构建和运行

源码 `user-programs/programs/maze-screen/maze_screen.c`，构建目标 `maze-screen`。
终端版 `maze` 已移除，现在仅保留屏幕版，沿用原迷宫生成算法和规则。

```powershell
.\build-tools\build.ps1 -Program maze-screen
```

ROM 加载 `kernel/build/kernel.hex`，UROM 加载本程序 `build/maze-screen.hex`。
产物均在源码自己的 build/ 中。使用图形调用 19/20，以 Busy/Yield 判断完成，
不要求图形完成中断；键盘仍是硬中断和内核队列投递的用户回调。

## 地图和操作

地图 15×11，每格 8×8 像素，占 120×88 区域，左上角为屏幕 (20,12)。
原算法是非递归随机深度优先生成：7×5 房间与连接通道构成连通迷宫。
起点 (1,1)，出口 (13,9)，只允许走通道，越界或撞墙按键被忽略。

- 深青灰（`0xA1EE`）整格：墙和 HUD。
- 米色（`0xF798`）：通道/背景。
- 珊瑚色（`0xED27`）实心 4×4：玩家。
- 小深青灰 2×2：起点，离开起点后恢复显示。
- 珊瑚色空心 6×6：出口，进入后通关。

使用 Digital 的 `0x8000 + RGB555` 调色板；颜色替换不增加矩形命令或改变迷宫算法。

- 顶部 S 后三位为步数，T 后三位为经过的秒数；均取模 1000。通关或 Q 退出时终端显示完整值。

WASD 移动，大小写都支持。R 保留当前地图、回起点并重置步数和计时；N 生成新地图，
Q 退出。进入出口会显示通关提示并 Exit(0)。随机种子来自时间和现有 PRNG 状态；
不承诺每张地图绝不重复，但不是固定的 Z 字走廊。时间 HUD 在重绘/移动时更新，
不是独立计时动画，空闲时不会为了更新数字主动唤醒用户。

## 局部绘制

启动清屏一次，然后画地图和 HUD；N 仅重新填充地图区域和变化数字。
同一行连续墙格合成一个矩形，减少启动时的调用数。
普通移动只清理旧玩家格、绘制新玩家块，地图不重画；离开起点还要补画起点标记。
HUD 仅重画变化数字，原 3×5 字体放大两倍后预存为 6×10（60 位）字模，
每个字符一次 `system.graphics.Bitmap`，同时写入前景与背景，不再先清除再逐行画矩形。
原每字符 6–9 次绘制改为 1 次，外观不变。
因此“更新两格”指地图部分，不包含数字变化所需的位图提交。

R 不重新生成或重画全部地图。无效按键不会导致绘图。
终端启动时仅打印一次操作帮助。正常游戏期间不输出，包括移动、N 新地图和 R 重置。
通关或 Q 退出时统一打印结果、当前这局的步数和用时（秒），随后 Exit(0)。
N/R 会重置这局的步数和计时；错误/队列溢出仍保留诊断并 Exit(1)。

## 中断和稳定性

沿用终端版的非嵌套键盘回调处理业务，图形 Busy 时调用 Yield，tick 不会被关闭。
新按键仍进入内核 FIFO，当前回调结束后依次处理；不在回调里调用 WaitEvent。
前台没有业务时使用 WaitEvent 等键盘。有限 FIFO 溢出被检测并报错退出。
每次绘制结束等最后一条填充完成再返回或退出，卡忙 10 秒报错；超时不取消硬件。

当前编译器可能把普通全局布尔缩窄成不支持的 i8 存储，重绘标志使用 volatile int。
数字更新的小循环禁用优化，规避展开后跨 draw_glyph 调用漏装栈偏移临时寄存器的路径，
回归覆盖 009→010 等数字更新。本次没有修改编译器后端。

## 验证

`tests/maze-screen/run_maze_screen.py` 执行真实内核/用户 BIN：检查 69 个连通通道格、
边界墙、玩家位置、普通移动局部更新、撞墙不重绘、R 保留地图、连续 N 产生不同布局、
路径求解并走到出口、Q 退出和回调完整现场恢复；验证帮助仅一次、游戏期间无输出、
两种正常退出均显示步数和用时。图形模型不产生完成 IRQ。
这是理想 ISA/设备模拟，不是 Digital 的微码/电路时序测试，仍需硬件加载验证。
