# 屏幕版五子棋

源码：`user-programs/programs/gomoku-screen/gomoku_screen.c`，目标 `gomoku-screen`。
替代原终端版 `tic-tac-toe`，保留其 **5×5 棋盘、两人交替、横竖或斜线连五获胜** 的规则。
这不是标准 15×15 五子棋，也没有 AI、禁手或悔棋。25 格填满且无人连五则平局。

## 构建与加载

在项目根目录运行：

```powershell
.\build-tools\build.ps1 -Program gomoku-screen
```

ROM 加载 `kernel/build/kernel.hex`，UROM 加载
`user-programs/programs/gomoku-screen/build/gomoku-screen.hex`。
源码目录只包含 C 文件、README 和 build/ 产物（s/o/bin/hex）。
复用现有图形系统调用 19/20/28、键盘订阅和内核事件队列，不新增系统调用、设备或微码。
内核不变时，也可直接运行 `./user-programs/build.ps1 -Program gomoku-screen`。

## 屏幕与输入

160×100 屏幕中，棋盘原点 (24,16)，每格 16×16，包含边框共 81×81 像素。
顶端列坐标 1–5，左侧行坐标 A–E；浅木色底、深棕网格和文字。
背景 `0xE28D`、网格 `0x9CA3` 使用 Digital 的 `0x8000 + RGB555` 调色板，
黑/白分别为 1/0；映射参考 [Digital GraphicComponent 源码](https://github.com/hneemann/Digital/blob/master/src/main/java/de/neemann/digital/gui/components/graphics/GraphicComponent.java)。

- 玩家 1：黑色实心圆，先手。
- 玩家 2：白色实心圆。
- 右侧 `P1` / `P2` 和 `TURN`：当前轮到的玩家。
- `BAD`：无效输入，重新输入完整坐标。
- `TAKEN`：格子已有棋子，不消耗当前玩家回合。
- `WIN` / `DRAW`：获胜或平局，最终棋盘保留，然后退出程序。
- 获胜的五颗棋子中心各加一个 4×4 红色标记，黑/白外圈仍可见，网格不受影响。
  横、竖、两条斜线均支持；同一落子形成多条连线时，标记原判断顺序找到的第一条
  （从上到下的行、从左到右的列、主对角线、副对角线）。平局和主动退出不加标记。

支持 `A3`、`3A`、`a3`、`3a`，输入第二个有效字符便自动落子，不用按 Enter。
不显示坐标文字：第一字符为字母时，以柔和蓝色（`0x99D8`）高亮该行矩形边框；
第一字符为数字时高亮该列矩形边框。输入第二字符后恢复网格并落子，状态栏只修改 P1/P2 数字。
CR/LF 被忽略，不会重复落子。Backspace、Delete 或 Esc 清除待输入坐标。
退格、取消、无效输入和占用落子均恢复原边框；CR/LF 保留待输入状态。
`Q` / `q` 随时退出（即使只输入了半个坐标），退出前也清除高亮。
例如：玩家 1 输入 A1，玩家 2 输入 2B，然后再次轮到玩家 1。

启动时在终端打印一次操作帮助，说明 A3/3A、首字符行列高亮、取消输入和 Q/q 退出。
屏幕不显示 Q QUIT 提示。正常对局中不打印终端；胜负/平局/主动退出时输出结果。
结束时调用 Exit(0)，内核按当前双进程设计打印退出日志并停机，复位可重新开始。
设备错误、等待超时或事件队列溢出打印诊断并 Exit(1)。

## 图形和事件处理

启动仅清屏一次，绘制网格、坐标和固定提示。正常落子只绘制新棋子和右侧
6×10 的玩家数字，P、TURN 文字以及网格不重画，也不清空整块状态栏。
每颗棋子为直径 10 像素的实心像素圆，保留原来的 80 个亮像素。
10×10 超过单次位图 64 位容量，因此拆成上下两个 10×5 透明位图，每块 50 位，
每块实际写入 40 个像素。0 位保留棋盘背景，不在运行时计算圆方程或展开掩码。
每颗棋子由 5 次矩形提交降为 2 次位图，图形寄存器写入由 40 次降为 22 次；
硬件扫描面积由 80 增至 100 个位置（其中 20 个不写），实际耗时收益由电路实测。
切换玩家数字使用一次 6×10 双色位图，包含清除旧数字。
第一坐标字符只提交 4 条一像素边框；第二字符用 4 条线恢复后，再画棋子和数字。
无遗留错误提示且未结束对局时，第二字符处理共 7 次绘制（4 条恢复边框、2 块棋子位图、
1 个玩家数字位图）；整个两字符回合共 11 次，上一版分别为 10 次、14 次。
获胜时额外提交五个红色中心标记，然后更新 WIN 提示；所有绘制完成后才输出结果并退出。
高亮/恢复只触碰既有网格线，不填充整行/整列，不覆盖已放置的棋子。
错误提示仅在变化时绘制或清除，胜负/退出时才替换 TURN 文字。
字体仍是 3×5 点阵放大两倍，预存为 6×10 的低/高字掩码。字母、数字和状态提示
均使用一次双色位图提交一个字符，不再运行逐行展开循环，不依赖字符显示硬件。
字符间距和颜色不变，字符串变短时仍清除整个提示区域，避免残留后缀。

每次矩形或位图提交前通过 Busy 查询确认设备空闲，忙时 Yield，让 tick 正常调度。
最后一次绘制也须完成后才返回回调或退出，避免新命令覆盖旧参数。
每次等待上限 10 秒，无屏幕完成中断；超时不尝试强制取消硬件任务。

初始化在 DeferEvents/ResumeEvents 保护区完成。之后棋盘、落子逻辑和绘图
仅由键盘回调访问；内核保证回调不嵌套，所以没有第二份用户按键队列。
绘图期间来的按键由内核 FIFO 暂存，当前回调返回后依次投递。
主循环只调用 WaitEvent，不轮询键盘；回调绘图中不使用 WaitEvent 等待完成。
内核 FIFO 有限，检测到 EventDrops 非零会安全退出，不承诺任意长度突发输入。

## 验证

`tests/gomoku-screen/run_gomoku_screen.py` 执行实际编译的内核/用户 BIN，检查：

- 初始空棋盘、配色像素和网格保留、仅更新棋子及玩家数字、首字符四条边框高亮。
- 两种坐标顺序、大小写、退格/Esc、无效和占用输入。
- 双方轮流、横/竖/两个斜向胜利、玩家 2 获胜、25 格平局。
- 棋子两块透明位图与原圆方程逐像素一致；五连子红标仅覆盖获胜棋子中心，
  边缘行/列、双连线优先级、平局/退出无标记、所有绘制完成后停机。
- 启动帮助仅输出一次、屏幕无 Q QUIT、正常对局不打印终端、退出、慢图形及 busy 卡死超时。
- 正常 tick、排队输入以及回调返回时完整寄存器/栈现场恢复。

这是理想 ISA/图形设备模型，不是 Digital 电路仿真，也不验证真实电路时序。
