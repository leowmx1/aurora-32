# 计算器跟踪版本

此目标与 [普通计算器](../calculator/README.md) 使用同一源文件，构建时增加
`AURORA_CALCULATOR_TRACE=1`。产物位于
`user-programs/programs/calculator/build/calculator-trace.hex`。

```powershell
.\build-tools\build.ps1 -Program calculator-trace
```

## 输出字段

| 格式 | 含义 |
|---|---|
| `{1}`、`{2}` 等 | 被接受事件的 16 位键盘 IRQ 序号，不是 ASCII 码 |
| `{!value}` | 无效签名事件字，打印整个事件值以便检查队列/现场 |
| `{P:tc=...,t0=...,v0=...,sp=...}` | 输入提交时，token 最后索引、首 token 类型/值、软件栈指针 |
| `{R:pp=...,p0=...,v0=...,sp=...}` | 转后缀后，后缀项数、首项类型/值、软件栈指针 |
| `{E:sp=...,base=...,err=...}` | 求值后栈顶、进入计算前栈基线、错误标志 |

`tc` 是最后一个 token 的索引，单个数字时是 0，不代表“没有输入”。
例如输入 `8`，输入阶段 `tc=0,t0=1,v0=8` 本身正确；转后缀后应有一个项，
成功求值后栈深相对 base 为 1。

## 用途与边界

用于区分：字符是否被接受、是否有重复事件、token 是否生成、后缀转换是否丢值、
软件栈是否恢复。发现 `{!0}` 说明读取到的字未满足签名约定，不是一个正常按键，
不应以“屏幕只是多输出几个符号”解释；结合序号和硬件现场定位原因。

跟踪输出会显著增加系统调用和终端访问次数，也可能影响中断发生的时机。
“跟踪版稳定、普通版不稳定”或相反都不能单独证明硬件/软件无问题。
同样不应依据本 README 承诺每个异常输入都能被恢复。
语法、退出键、算术限制和队列限制与普通版一致。
