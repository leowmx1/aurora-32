# 屏幕版贪吃蛇

## 构建与加载

这是新建的用户程序，源码为 `user-programs/programs/snake-screen/snake_screen.c`。
原来的终端版已从项目移除，现在仅保留本显存版贪吃蛇。

```powershell
# 项目根目录
.\build-tools\build.ps1 -Program snake-screen
```

ROM 加载配套 `kernel/build/kernel.hex`，UROM 加载
`user-programs/programs/snake-screen/build/snake-screen.hex`。其他产物 `.s/.o/.bin`
也在本程序的 build/ 中。运行依赖图形系统调用 19、20、MIDI 系统调用 22..27 和正常 tick、键盘回调。
本版增加内核音序器，必须同时重新加载配套内核和用户 HEX，不能沿用旧内核。
不注册图形 IRQ，不要求硬件屏幕完成中断；设备完成后须将 0x09000009 的 busy 清零。

## 画面与控制

画面 160×100，棋盘仍为 12×8 格，每格 10×10 像素，逻辑原点 (20,16)，
蛇块 8×8，格子之间留背景色间隔。棋盘外围有 2 像素边框。

- 低饱和深灰蓝（`0x8CA7`）：背景。
- 柔和绿色（`0xB2F0`）大块：蛇身和 HUD。
- 金色（`0xFF2C`）大块：蛇头。
- 珊瑚色（`0xFDAB`）小块：食物，仅 4×4，与蛇头大小和颜色不同。
- 柔和绿色边框：运行；金色边框：未开始、暂停或结束。
- 顶部 `S` 后三位数字是分数，`T` 后三位数字是设置的毫秒/步，例如初始 `S000 T020`。

字形保留原 3×5 点阵放大 2 倍的外观，预存为 6×10（60 位）位图；不依赖终端定位、字体硬件或
任意像素直写接口。启动时向终端打印一次操作帮助（空格、WASD、P、M、速度范围和 Q），
随后游戏运行中不打印终端；退出时输出结果，错误退出保留诊断。

| 操作 | 行为 |
|---|---|
| 空格 | 开始；开始后切换暂停 |
| W/A/S/D | 上/左/下/右，大小写均可 |
| P | 暂停或继续 |
| M/m | 音乐和音效总开关（默认开启），开局前/运行/暂停/结束旋律时均可用 |
| + 或 = | 每次减少 10 ms/步，最小 10 |
| - | 每次增加 10 ms/步，最大 150 |
| Q | 显示退出提示并 Exit(0) |

规则与终端版相同：初始长度 3、向右；一移动间隔最多接受一次有效转弯，不能直接
反向；吃一个食物增长一格并得一分；撞墙或撞身体结束；不增长时允许进入即将移走
的旧尾格；占满 96 格获胜。食物仅从空格中选，随机状态由 timer 初始化。
游戏结束退出码为 0；系统调用错误、队列溢出或图形超时以 1 退出。

## 绘制与性能

启动只做一次 160×100 背景填充，并画边框、初始蛇/食物和 HUD。
使用 Digital 的 `0x8000 + RGB555` 调色板值；只是替换颜色，不增加绘制命令。
随后缓存每个格子上次已绘制的类别，只重画变化的格子：

- 普通未吃食物的移动通常只写 3 个 8×8 矩形：清旧尾、旧头变身体、新头。
- 吃到食物时更新新的食物格和变化的蛇格，不清全屏。
- HUD 仅重画发生变化的数字；每个字符通过一次 `system.graphics.Bitmap` 绘制。
  0 位同时恢复背景，省去单独清除字符和逐行画矩形；运行时不再展开字模。
  原每字符 6–9 次绘制改为 1 次，字体尺寸、间距和配色不变。
- 边框仅在运行/暂停/结束状态对应的颜色变化时重画。
- 分数、速度和暂停状态只更新屏幕，不打印终端，避免吃食物时被终端输出阻塞。

`FillRect` 提交后，下一次参数写入前通过 Busy 查询确认空闲，并在忙时 Yield。
每一帧结束还会确认最后一个填充已完成，再开放用户回调或退出；图形等待最多 10 秒。
超时不会取消硬件任务。这里不会用 WaitEvent 等待图形设备，因为它没有完成事件。

默认速度为 20 ms/步，范围仍为 10..150。计时从上一帧绘制完成后开始，
所以实际移动间隔还包含绘图和系统调用开销，并不保证 10 ms 设置就达到 100 FPS。
慢绘图后不突发追赶多步；这是保留的原版行为。

## 中断与状态安全

键盘由硬中断进入内核事件队列，再执行用户回调 `process_key`。回调不画图。
前台在 `DeferEvents`/`ResumeEvents` 之间更新游戏状态和渲染，避免回调在绘制过程中
改写游戏数据。暂缓只影响用户回调投递：tick 和键盘 IRQ 继续处理，按键保存在内核 FIFO。
长时间卡忙可能填满有限 FIFO，示例检测 EventDrops 后报错退出，不承诺无限输入容量。

未开始或暂停时先停止声音，再 WaitEvent 等键盘事件。运行中计算下一步的剩余毫秒数，
通过 `system.Sleep(remaining)` 阻塞，不再一直 Yield 查询时间。键盘事件可提前唤醒，
转向、暂停、变速、M 和 Q 无须等完整步长；唤醒后重算状态和期限，不因转向重新睡满整个步长。
剩余时间在 DeferEvents 区内计算，ResumeEvents 后再 Sleep；内核 wake_pending 避免两者之间漏唤醒。
到期精度受 tick 周期影响，建议不大于 10ms；用户绘图等待仍采用 Busy/Yield。
没有新增定时回调或第二个用户进程，不执行用户 DI/EI/HALT，也不修改电路或微码。

## 简短背景旋律与音效

启动 `system.midi.Program(0)` 选择音色 0，使用新增的 Sequence / SequenceBusy 系统调用。
开局前安静，按空格后播放开局提示，再进入轻声背景旋律。

| 场景 | MIDI 音符顺序 | 单音长度 | 力度 |
|---|---|---|---|
| 开局 | 72、76、79 | 90 ms | 90 |
| 背景循环 | 《贪吃蛇大作战》开头四小节，22 个音符及休止 | 附点与长短音，约 128 BPM | 42 |
| 吃食物 | 84、88、91 | 70 ms | 90 |
| 撞墙/撞自己 | 67、63、60、48 | 前三个 130 ms，最后 220 ms | 90 |
| 填满胜利 | 72、76、79、84 | 前三个 110 ms，最后 260 ms | 90 |

背景参考[公开曲谱预览](https://www.tan8.com/yuepu-57642.html)，仅取开头四小节主旋律，
不是完整原曲或原录音；不带和弦伴奏。选曲依据为 2016 年《贪吃蛇大作战》，
无法保证与用户记忆中的其它贪吃蛇版本相同。
背景每个十六分音符单位为 117 ms，发声约占时值的 3/4，剩余留空；休止不发送音符 0。
背景一轮理论约 7.49 秒。其他音效音符之间留 30 ms 间隔，吃食物提示约 0.3 秒，
出局约 0.73 秒，胜利约 0.71 秒；实际发声边界受 tick 周期和关中断时间影响，非硬实时。
只使用一个通道和同一音色：音效临时冻结背景进度，结束后从被打断的位置续播；新食物提示可重启旧提示，
出局/胜利优先。每次换音/中断都先松开旧音，不叠加未释放音符。

音符表提交后复制到内核，由 tick 按固定时间线推进，不依赖用户绘图循环。
延迟服务不会把每次延迟累积到下一拍；错过的音符跳过，不突发补播。
tick 越稀疏，节拍抖动越明显，建议周期约 5..10 ms；绘图完成仍采用轮询，不增加硬件中断。
键盘回调仅改状态，不执行音乐序列。暂停立即取消当前提示/背景，继续时从背景开头播放。
声音默认开启，M/m 是总开关，关闭时前台停止当前音符并取消后续序列，所有音效都静音。
再次开启：运行中从背景开头恢复，暂停或未开始时保持安静；不补播静音期间错过的音效。
关闭结束旋律会直接进入退出流程。M 切换不打印终端、不重画棋盘，
也不重置蛇的移动计时；和其它按键一样须等内核投递回调，非硬件级零延迟静音。
出局或胜利冻结棋盘，等待短旋律结束后退出；期间每次 Sleep(20) 后检查 SequenceBusy，
不是连续 Yield。音乐仍由内核 tick 推进，键盘事件可以提前唤醒，Q 可提前退出。
内核在退出和用户异常时兜底释放活动音符。音乐不改变移动、计分和食物生成算法。
硬件需接好 0x0A MIDI 区和 PC 输入；详见 [MIDI 内核接口](../../kernel/midi.md)。

## 验证范围

`tests/snake-screen/run_snake_screen.py` 执行生成的内核/用户 BIN，不再依赖已删除的终端版源码。
在理想设备模型中检查初始像素、HUD
字形、普通移动的三矩形更新、转向、暂停、调速、增长、食物位置、撞墙和退出。
同时验证吃食物提示、暂停取消、出局旋律及音符释放，所有设备写入均在内核态完成。
测试 M 的大小写、运行中释放、暂停时开启仍安静、恢复音乐、取消结束旋律，
以及全程静音仍能吃食物/计分/出局且不发送音符命令。
`audio_contract.c` 复用游戏音符表和提交逻辑，在独立测试入口验证完整开局/背景循环/食物/出局/胜利
音符序列及 timer 跨越 2^32 回绕；胜利声音测试不等同于实际玩满 96 格。
绘制期间发生 tick 和键盘回调，检查完整用户现场恢复。
`tests/midi-syscall/run_sequence.py` 还检查前台纯计算、长时间绘图时的独立播放、固定节拍和食物音效后的续播位置。

这些测试不是 Digital 电路仿真，实际显示效果、硬件性能仍需在电路中验证。
