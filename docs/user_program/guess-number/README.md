# 猜数字

源文件：[guess_number.c](../../../user-programs/programs/guess-number/guess_number.c)。
产物：`user-programs/programs/guess-number/build/guess-number.hex`。
通过键盘中断回调接收输入，通过 `system.io` 输出，无需增加内核系统调用。

## 操作流程

1. `Lower bound >`：输入下限，按 Enter。
2. `Upper bound >`：输入上限，按 Enter，上限必须大于或等于下限。
3. 程序在包含两端点的范围内选择答案，打印 `Range: [lower, upper]`。
4. `Guess >`：输入猜测并按 Enter，得到 `Too low.` 或 `Too high.`。
5. 猜中显示 `Correct! The number was ... Attempts: ...`，退出码为 0。

所有输入阶段都支持 `Q` 或 `q` + Enter 退出，输出 `Quit.`。
Backspace（8）或 DEL（127）删除最后一个尚未提交字符，并输出 `\b \b` 擦除回显；
显示效果取决于电路终端对退格控制字符的支持。
兼容 CR、LF、CRLF，CRLF 只提交一次。

## 范围与合法性

支持 `-2147483648` 到 `2147483647` 的完整有符号 32 位范围，包括全负区间、
跨零区间、单点区间和整个 32 位有符号空间。允许可选 `+/-` 及首尾空格。
空行、只有符号、夹杂非数字、超出 32 位范围均为无效整数。

例如下限 `-50`、上限 `100`，答案位于闭区间 `[-50,100]`。
下限和上限都为 `-7` 时答案必定是 -7，但仍需提交一次猜测才结束。
上限错误只要求重新输入上限，不丢弃已设置的下限。

猜测超出所选范围或格式错误不计次数；在范围内的合法猜测（包括猜中一次）才计数。
计数器在 INT_MAX 饱和，避免计数溢出。输入缓冲区为 32 个字，最多保留 31 个字符；
继续输入会提示过长并清空当前行。清空后后续字符可组成新行，不能当作任意长粘贴过滤器。

## 实现

`phase` 表示输入下限/输入上限/猜测三个阶段。`parse_integer` 先逐位检查十进制
幅值上限，再转成有符号结果；`signed_word` 特别避免对 INT_MIN 直接取负导致溢出。
文本缓冲区使用 `int line[32]`，每字符一个硬件字，避开当前可写 char 数组的窄存储问题。

伪随机状态使用 `state = state * 1664525 + 1013904223` 的 32 位无符号序列。
收到输入时会混入系统毫秒数和键盘事件字，使答案受到用户输入时机影响；
不直接访问内核 timer，也不是密码学随机源。
`span = (unsigned)high - (unsigned)low + 1` 以无符号运算覆盖跨零范围。
span 为 0 表示恰好 2^32 种值，直接使用完整采样值；其余范围采用拒绝采样后取模，
避免通常的简单取模范围偏差，也避免对 0 取余。

键盘事件由内核按 FIFO 保存，并从队列取出后进入普通 C 回调；用户程序不再维护事件队列或过滤序号。
回调直接处理业务，可以输出、调用普通函数和被 tick 抢占；键盘与 Telnet 回调互不嵌套。
主循环使用 `system.WaitEvent()` 等待，事件到达后由内核唤醒。
内核 FIFO 可用 63 槽，满时丢新事件并累计 `system.EventDrops()`；本示例检测到溢出便提示并以代码 1 退出，避免继续使用缺失输入。

## 构建与验证

```powershell
.\build-tools\build.ps1 -Program guess-number
```

已进行编译检查及宿主逻辑测试：整数边界、8 万次不同范围采样、输入解析、
偏大/偏小、退格、CRLF、队列满及退出。宿主测试不模拟中断微码或真实 CPU 时序。
在电路上建议先试 `[-10,10]`，再试 `[-7,-7]`、INT_MIN 单点区间，以及 Q 退出。
